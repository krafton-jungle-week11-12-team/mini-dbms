# mini-DBMS

## 저장 형식: CSV

테이블 데이터는 테이블마다 CSV 파일 하나로 저장해요. (2026-11-16 결정)

| 형식 | 장점 | 단점 | 쓰는 곳 |
| --- | --- | --- | --- |
| **CSV** | 사람이 바로 읽을 수 있어 디버깅이 쉽고 구현이 간단해요 | 값에 쉼표·따옴표·줄바꿈이 있으면 이스케이프가 필요하고, 숫자도 문자로 저장돼요 | 우리 구현 |
| 고정 길이 바이너리 | N번째 행의 위치를 바로 계산할 수 있어요 | 짧은 값도 칸을 다 차지하고, 칸보다 긴 값은 저장할 수 없어요 | - |
| 가변 길이 바이너리 (페이지) | 공간 효율이 좋고 긴 값도 저장할 수 있어요 | 구현이 가장 복잡해요 | SQLite, MySQL InnoDB |

과제 기간 안에 Phase 1~3을 모두 끝내는 게 우선이라, 구현과 디버깅이 가장 쉬운 CSV를 골랐어요.
Phase 2의 B+ 트리에는 `id → 행 시작 바이트 오프셋`을 저장해요. 그래서 CSV여도 `WHERE id = ?` 조회는 해당 위치로 바로 이동(seek)해 한 행만 읽어요.
