# ADR 0002. 개발 언어

2026-11-16

이 문서를 읽으면 이 프로젝트가 Python 3.10 이상을 쓰기로 한 이유와, C·Go·Java를 쓰지 않은 이유를 알 수 있어요.

## 후보

- Python
- C
- Go
- Java

## 비교

| 언어 | 장점 | 단점 |
| --- | --- | --- |
| Python | mini-redis와 같은 언어라 클라이언트·서버 틀·테스트 구조를 재활용해요. 표준 라이브러리(`csv`, `threading`, `queue`, `http.server`)만으로 충분해요 | GIL 때문에 CPU 연산은 한 번에 한 스레드씩 실행돼요 |
| C | 가장 빠르고, pthread로 진짜 병렬 실행돼요 | HTTP 파싱, 문자열 처리, 메모리 관리를 모두 직접 해야 해서 가장 느리게 만들어요 |
| Go | 빠르고, 고루틴으로 병렬 실행돼요 | 팀 경험이 거의 없어요 |
| Java | 빠르고, 스레드 풀이 표준에 있어요 | 팀 경험이 거의 없어요 |

## 결정

Python 3.10 이상, 표준 라이브러리만으로 만들어요. 테스트는 pytest로 해요.

## 결정 이유

- Phase 1~3을 이틀 안에 끝내야 해서, 팀이 바로 쓸 수 있고 재활용할 코드가 있는 언어가 필요해요.
- 100만 건에서도 인덱스 조회와 선형 탐색의 차이(밀리초 미만 대 수 초)는 Python으로 충분히 보여요.
- GIL이 있어도 파일·네트워크 입출력 중에는 다른 스레드가 일하고, id 중복이나 lost update 같은 경쟁 상태는 똑같이 생겨요. 그래서 스레드 풀과 락 설계의 의미는 그대로예요.
