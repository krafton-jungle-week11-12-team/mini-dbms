# ADR 0001. 테이블 저장 형식

2026-11-16

## 후보

- CSV
- 고정 길이 바이너리
- 가변 길이 바이너리 (페이지)

## 비교

| 형식 | 장점 | 단점 | 쓰는 곳 |
| --- | --- | --- | --- |
| CSV | 사람이 바로 읽을 수 있고 구현이 간단해요 | 쉼표·따옴표·줄바꿈은 이스케이프해야 하고, 숫자도 문자로 저장돼요 | - |
| 고정 길이 바이너리 | N번째 행 위치를 바로 계산해요 | 짧은 값도 칸을 다 차지하고, 긴 값은 못 넣어요 | - |
| 가변 길이 바이너리 (페이지) | 공간 효율이 좋고 긴 값도 넣을 수 있어요 | 구현이 가장 복잡해요 | SQLite, MySQL InnoDB |

## 결정

테이블마다 CSV 파일 하나로 저장해요.

## 결정 이유

- 과제 기간 안에 Phase 1~3을 모두 끝내는 게 우선이라, 구현과 디버깅이 쉬운 형식이 필요해요.
- B+ 트리에 `id → 행 시작 바이트 오프셋`을 저장하면, CSV여도 `WHERE id = ?`는 그 위치로 바로 이동(seek)해 한 행만 읽어요.
