# ADR 0004. 락 전략

2026-11-16

이 문서를 읽으면 여러 워커가 같은 테이블을 동시에 다룰 때 테이블별 락으로 시작하기로 한 이유를 알 수 있어요. 서버 구조와 스레드 풀은 [0003. 서버 구조와 스레드 풀](0003-server-architecture.md)에서 다뤄요.

## 후보

- 전역 락 하나
- 테이블별 락
- 테이블별 읽기/쓰기 락

## 비교

| 후보 | 장점 | 단점 |
| --- | --- | --- |
| 전역 락 | 가장 쉬워요 | 모든 요청이 한 줄로 처리돼요 |
| 테이블별 락 | 쉽고, 다른 테이블끼리는 동시에 처리해요 | 같은 테이블의 SELECT끼리도 기다려요 |
| 테이블별 읽기/쓰기 락 | SELECT끼리 동시에 처리해요 | 표준 라이브러리에 없어서 직접 만들어야 해요 |

## 결정

락은 테이블별 락으로 시작하고, 시간이 남으면 테이블별 읽기/쓰기 락으로 바꿔요.

## 결정 이유

- 마감이 가까워서 락은 쉬운 것부터 시작해요.
- INSERT의 id 발급, CSV 덧붙이기, B+ 트리 삽입을 같은 락 안에 묶으면 id 중복과 행 섞임을 막을 수 있어요.
