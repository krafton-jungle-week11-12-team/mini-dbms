# Phase 4 요구사항

이 문서를 읽으면 Phase 3 API 서버에 스레드 풀과 테이블별 락을 붙여 여러 요청을 동시에 처리하려면 서버, 메인 스레드, 워커 스레드, 실행기가 무엇을 해야 하는지 ID로 확인할 수 있어요.
Phase 3 요구사항은 [phase3.md](phase3.md)에 있어요.

처리 흐름: `클라이언트 → OS 대기열 → 메인 스레드(accept → put) → 작업 큐 → 워커 스레드(get → 요청 처리 → 응답) → engine.execute(sql) → 실행기(테이블 락 안에서 실행)`

- 메인 스레드는 연결을 받아 작업 큐에 넣기만 하고, 요청을 읽고 처리하는 일은 워커 스레드가 해요.
- 토크나이저, 파서, AST 검증은 공유 상태를 바꾸지 않아서 락 없이 동시에 실행돼요. `next_id`, B+ 트리, CSV를 다루는 실행기만 테이블 락 안에서 실행돼요.
- 스레드 풀 구조는 [ADR 0003. 서버 구조와 스레드 풀](../adr/0003-server-architecture.md), 락 단위는 [ADR 0004. 락 전략](../adr/0004-locking.md)을 따라요.
- 서버가 워커 스레드 객체를 어떻게 보관하고 관리할지(종료 시 정리 방법 등)는 아직 정하지 않았어요. 정해지면 이 문서에 요구사항으로 추가해요.

## 서버

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| TP-01 | 서버는 시작할 때 워커 스레드 N개와 크기 M인 작업 큐를 만든다. | N = 4, M = 16. 작업 큐는 `queue.Queue(maxsize=M)`예요 |

## 메인 스레드

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| TP-02 | 메인 스레드는 작업 큐가 가득 차지 않았다면, OS 대기열에 들어온 연결을 `accept()`로 꺼내 (소켓, 주소)를 작업 큐에 넣는다. 메인 스레드는 요청 내용을 읽지 않는다. | `process_request`에서 작업 큐에 넣기만 해요 |
| TP-03 | 작업 큐가 가득 찼다면 메인 스레드는 연결을 `accept()`한 뒤 503 응답을 보내고 소켓을 닫는다. | `put_nowait()`가 실패하면 거절해요. 거절한 요청은 나중에 처리하지 않아요. 응답 구조는 설계 문서에서 정해요 |

## 워커 스레드

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| TP-04 | 놀고 있는 워커는 작업 큐에서 (소켓, 주소)를 꺼내, 소켓에서 HTTP 요청을 읽고 처리한 뒤 응답을 쓰고 소켓을 닫는다. | `get()` → `finish_request()` → `shutdown_request()` |
| TP-05 | 모든 워커가 처리 중이면 작업은 작업 큐에서 기다린다. 작업 큐가 비어 있으면 워커는 작업이 들어올 때까지 기다린다. | |
| TP-06 | 요청 처리 중 예외가 나도 워커 스레드는 죽지 않고 다음 작업을 꺼내야 한다. | 지키지 않으면 에러가 날 때마다 워커가 하나씩 줄어들어요 |
| TP-07 | 처리 결과와 관계없이 소켓은 반드시 닫아야 한다. | `try`/`finally` |
| TP-08 | 워커는 소켓에서 요청을 읽을 때 5초 동안 데이터가 오지 않으면 읽기를 포기하고 소켓을 닫는다. | `QueryHandler.timeout = 5`. 한 번 읽을 때마다 5초를 기다려요. 느린 클라이언트가 워커를 오래 붙잡지 않게 해요 |

## 실행기

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| LK-01 | 실행기는 테이블마다 락을 하나씩 가진다. | `locks = {table: threading.Lock()}` |
| LK-02 | 실행기는 INSERT와 SELECT를 실행하는 동안 그 문장이 다루는 테이블의 락을 잡는다. 같은 테이블의 INSERT와 SELECT는 같은 락을 쓴다. | SELECT도 락을 잡아야 INSERT가 쓰는 도중의 B+ 트리나 CSV를 읽지 않아요 |
| LK-03 | INSERT는 id 발급, CSV 추가, 인덱스 삽입을 한 번 잡은 락 안에서 모두 끝낸다. | Phase 2 `EXE-06`의 순서(id 부여 → `append()` → 트리 삽입 → `next_id` 증가) 전체를 한 락으로 묶어요 |
| LK-04 | 실행이 성공하든 예외가 나든 락은 반드시 놓는다. | `with` 문 |
