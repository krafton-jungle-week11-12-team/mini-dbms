# Phase 1 요구사항

이 문서를 읽으면 Phase 1 SQL 처리기가 단계별로 무엇을 해야 하는지 ID로 확인할 수 있어요.
자세한 문법, 토큰 기준, AST 구조, 에러 처리는 설계 문서(작성 예정)에 정리해요.

처리 흐름: `CLI → 토크나이저 → 파서 → AST 검증 → 실행기 → 저장 계층(CSV)`

## CLI

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| CLI-01 | 사용자는 SQL 파일 경로를 인자로 주어 처리기를 실행할 수 있어야 한다. | 예: `./mini-dbms query.sql` |
| CLI-02 | SQL 파일이 없거나 존재하지 않으면 1을 반환하고 종료해야 한다. | 설계 문서 "에러 처리" |
| CLI-03 | 인자가 2개가 아니면 1을 반환하고 종료해야 한다. | 한 번에 SQL 파일 하나만 실행. 설계 문서 "에러 처리" |
| CLI-04 | `;`를 기준으로 명령어를 분리해야 한다. | 빈 명령어(`;;`)와 짝이 없는 따옴표는 파서가 처리. 설계 문서 "에러 처리" |
| CLI-05 | 분리한 명령어를 하나씩 파싱 함수에 전달해야 한다. | |

## 토크나이저

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| TOK-01 | 문장을 토큰 단위로 잘라야 한다. | 키워드는 대소문자 구분 안 함. 설계 문서 "토큰 기준" |
| TOK-02 | 각 토큰의 유효성을 검사해야 한다. | 설계 문서 "에러 처리" |

## 파서

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| PAR-01 | 토크나이저의 결과를 받아 AST를 만들어야 한다. | 설계 문서 "AST 구조" |
| PAR-02 | AST를 만들며 토큰의 유효성을 검사해야 한다. | 설계 문서 "에러 처리" |
| PAR-03 | INSERT 문과 SELECT 문을 정해진 문법에 따라 해석해야 한다. | 설계 문서 "문법" |
| PAR-04 | 형식이 맞지 않으면 기대한 토큰, 실제로 온 토큰, 위치를 포함한 에러를 내고 AST를 반환하지 않아야 한다. | 설계 문서 "에러 처리" |

## AST 검증

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| AST-01 | 파서가 완성한 AST를 실제 스키마와 비교해 검사해야 한다. | 테이블 존재, 값 개수, 값 타입, 컬럼 존재. 설계 문서 "에러 처리" |

## 실행기

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| EXE-01 | AST의 종류에 따라 다른 동작을 해야 한다. | 지원: INSERT, SELECT |
| EXE-02 | INSERT 시 저장 계층의 `append()`를 호출하고, 반환받은 오프셋을 인덱스에 등록해야 한다. | 인덱스 등록은 Phase 2 |
| EXE-03 | SELECT 시 WHERE 조건에 해당하는 행을 골라 반환해야 한다. | |

## 저장 계층

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| STO-01 | 레코드를 파일 끝에 추가하고 그 행의 시작 오프셋을 반환하는 함수를 가져야 한다. | 쓰기 전 `tell()` 값이 시작 오프셋 |
| STO-02 | 파일을 처음부터 끝까지 읽어 전체 행 이터레이터를 반환하는 함수를 가져야 한다. | Phase 2 재사용을 위해 오프셋도 함께 반환 |
