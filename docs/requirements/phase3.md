# Phase 3 요구사항

이 문서를 읽으면 Phase 3 API 서버가 클라이언트의 SQL 요청을 받아 어떻게 응답해야 하는지 ID로 확인할 수 있어요.
Phase 1·2 요구사항은 [phase1.md](phase1.md), [phase2.md](phase2.md)에 있어요.

처리 흐름: `클라이언트 → HTTP POST /query → API 서버 → engine.execute(sql) → (Phase 1·2 엔진) → HTTP 응답`

- 서버와 엔진을 연결하는 방식은 [ADR 0003. 서버 구조와 스레드 풀](../adr/0003-server-architecture.md)을 따라요.
- 스레드 풀과 동시 요청 처리 요구사항은 아직 이 문서에 없어요.

## 클라이언트

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| CLT-01 | 클라이언트는 API 서버에게 SQL 요청을 보낼 수 있어야 한다. | HTTP `POST` 메서드. 요청당 SQL 한 문장 |

## API 서버

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| SRV-01 | API 서버는 SELECT가 성공하면 상태 코드와 조회 결과를 응답해야 한다. | 상태 코드 200. 응답 구조(포함하는 필드)는 설계 문서에서 정해요 |
| SRV-02 | API 서버는 INSERT가 성공하면 상태 코드와 삽입 결과를 응답해야 한다. | 상태 코드 201. 응답 구조(포함하는 필드)는 설계 문서에서 정해요 |
| SRV-03 | API 서버는 SQL 실행이 실패하면 상태 코드와 에러 정보를 응답해야 한다. | |
| SRV-04 | API 서버는 요청 형식이 잘못되면 상태 코드와 에러 정보를 응답해야 한다. | |
| SRV-05 | API 서버는 요청 처리가 실패해도(잘못된 요청, 엔진 내부 오류 포함) 종료되지 않고 이후 요청을 정상 처리해야 한다. | 실패한 요청에는 4xx/5xx로 응답하고, 내부 오류 상세는 서버 로그에만 기록 |
| SRV-06 | API 서버의 모든 응답은 동일한 JSON 구조를 따라야 한다. | |
